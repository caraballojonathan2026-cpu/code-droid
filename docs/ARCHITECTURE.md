# code-droid architecture

## Design goals

1. **Run on 4 GB RAM.** Every component replaces a heavyweight standard piece with the
   lightest thing that still does the real job.
2. **No moving parts you can't see.** The build is 7 explicit commands; the IDE is 4 static files.
3. **Zero npm/JS dependencies.** `npm install` is a no-op; the supply chain is tiny; startup is instant.

## Components

### Web IDE (`web/`, ~150 KB)

| Standard choice | code-droid choice | Why |
|---|---|---|
| Monaco editor (~3.5 MB) | overlay editor: transparent `<textarea>` over a syntax-highlighted `<pre>` | ~40 lines of CSS/JS, instant load, smooth on weak CPUs |
| tree-sitter / TextMate grammars | single-pass regex tokenizer (`kotlin.js`) | small files highlight in <1 ms; no wasm |
| React/Vue SPA | vanilla JS + `fetch` | no build step for the IDE itself |
| WebSocket build stream | request/response JSON with per-step timings | simpler; SSE streaming is on the roadmap |

### Server (`server/`, Node ≥ 16, zero deps)

- `server.js` — static file serving + JSON API (`/api/tools`, `/api/projects`, `/api/files`,
  `/api/file`, `/api/build`, `/api/apk`). Single-flight build lock: low-RAM machines
  should never run two compilers at once.
- `store.js` — projects live under `projects/`; every path is resolved and verified to stay
  inside the project (no `../..` escapes); `build/` is server-managed.
- `toolchain.js` — discovery order: `CODE_DROID_TOOLS` → `tools/` → `ANDROID_HOME` → `~/Android/Sdk` → `$PATH`.
  Newest `build-tools/*` and `platforms/android-*` win.
- `builder.js` — the pipeline (below). Each step is `execFileSync` with captured stdout/stderr
  and wall-time, returned as JSON for the console view.

### The direct build pipeline

```
res/ ──► aapt2 compile ──► res.zip ─┐
AndroidManifest.xml ────────────────┼─► aapt2 link ─► unsigned.apk + gen/R.java
android.jar ────────────────────────┘         │
kt sources ─► kotlinc (-cp android.jar) ─► classes ─► d8 (+kotlin-stdlib.jar)
                                                          │ classes.dex
unsigned.apk ◄── zip -j unsigned.apk classes.dex ◄────────┘
unsigned.apk ─► zipalign -f -p 4 ─► aligned.apk ─► apksigner (debug key) ─► app-debug.apk
```

Notes:

- **kotlin-stdlib is dexed into every APK.** That's what makes "Kotlin just works" without
  a dependency system. Cost: ~+1.3 MB on a hello-world APK. R8/ProGuard stripping is a
  roadmap item (d8 has no tree-shaker; R8 ships in the same build-tools folder — easy add).
- **R.java** is generated by `aapt2 link --java gen/` and compiled with `javac`
  (kotlinc uses it for symbol resolution; javac emits its bytecode deterministically).
- **Debug keystore** is generated once by `keytool` (ships with every JDK) at
  `tools/debug.keystore`, password `android` — same convention as Google's own debug key.
- **Memory tuning:** `kotlinc` honours `JAVA_OPTS` (we cap at `-Xmx1024m` by default).
  Concurrent builds are refused by design.

## Threat model / safety

- Path traversal: all file APIs resolve against the project root and reject escapes.
- The server never shells out with user input: tools receive fixed argument arrays
  (`execFileSync`, no `sh -c`).
- The debug key is for development only — never sign releases with it.

## Why this is enough (and when it isn't)

For learning, prototyping, small apps and offline-first workflows, the framework
`Activity` + Views APIs cover a lot: UI in Kotlin, intents, sensors, storage, network.
The moment you need AndroidX/Compose/NDK, code-droid should grow an opt-in module —
the roadmap issue tracker is the place to help shape that.
